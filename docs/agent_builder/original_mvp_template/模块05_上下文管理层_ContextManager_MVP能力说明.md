# 模块 05：上下文管理层 / Context Manager MVP 能力说明

## 1. 当前模块

当前讨论模块：

```text
模块 05：上下文管理层 / Context Manager
```

上下文管理层负责在每次模型调用、规则判断、工具规划前，整理当前任务所需的信息。

它不是简单把全部工程数据丢给模型，而是构造一个受控的 Context Package。

MVP 中，上下文管理层的核心目标是：

```text
让模型知道当前任务所需的必要信息；
让规则和工具知道当前工程环境；
避免模型拿到过多、无关或敏感的工程原始数据；
保证上下文来源可追踪。
```

---

## 2. 本模块在 MVP 总体流程中的位置

整体流程中，上下文管理层位于配置加载之后、意图识别和参数提取之前。

```text
用户输入
↓
前端提交任务
↓
Agent 配置中心加载配置
↓
Orchestrator 创建 run_id
↓
Context Manager 加载上下文
↓
生成 Context Package
↓
IntentRouter 使用上下文识别意图
↓
AgentRouter 使用上下文判断业务 Agent
↓
LLM 使用上下文提取参数
↓
Rule Engine 使用上下文补默认值和校验
↓
Tool Planner 使用上下文生成工具计划
```

本模块主要覆盖：

```text
项目上下文加载；
软件模块上下文加载；
当前对象上下文加载；
会话上下文加载；
Agent 配置上下文加载；
工具可用性上下文加载；
知识与规则版本上下文加载；
Context Package 构造；
上下文脱敏与裁剪；
上下文写入 Trace。
```

---

## 3. 模块定位

上下文管理层的定位是：

```text
为每一次模型调用和工作流节点提供必要、准确、结构化、可追踪的上下文。
```

它解决的问题是：

```text
1. 模型不知道用户当前在哪个项目；
2. 模型不知道用户当前选中了什么对象；
3. 模型不知道当前软件模块是什么；
4. 模型不知道当前可用工具有哪些；
5. 模型不知道当前 Agent 的能力边界；
6. 模型不知道当前规则版本和项目配置；
7. 模型拿到太多原始工程数据，导致不可控；
8. 多轮对话中模型忘记前面的任务状态。
```

Context Manager 不是：

```text
1. 大模型；
2. 规则引擎；
3. 业务执行器；
4. 软件 Adapter；
5. 长期知识库；
6. 全量工程数据库。
```

一句话：

```text
上下文管理层决定“这一次让模型知道什么”。
```

---

## 4. MVP 必须构造的 Context Package

MVP 中，每次关键模型调用前，都应生成 Context Package。

最小结构建议：

```json
{
  "run_id": "",
  "session_id": "",
  "user_input": "",
  "main_agent": {},
  "routed_agent": {},
  "current_project": {},
  "current_module": {},
  "selected_objects": [],
  "workflow_state": "",
  "available_tools": [],
  "schema_version": "",
  "rule_version": "",
  "skill_version": "",
  "model_policy": {},
  "user_permission": {},
  "conversation_summary": "",
  "draft_object": {},
  "constraints": []
}
```

---

## 5. Context Package 应包含哪些信息

### 5.1 用户输入

```text
用户本轮自然语言；
用户上一轮补充内容；
用户明确确认过的参数；
用户明确否定过的内容。
```

示例：

```text
用户说：帮我创建一个高速公路路基模板，设计速度 80，路基宽度 24.5。
```

---

### 5.2 当前 Agent 信息

包括：

```text
总体 Agent；
本次调用业务 Agent；
Agent 能力边界；
Agent 禁止事项；
Agent 当前版本；
Agent 绑定的 Schema / Prompt / Skill / Rule 版本。
```

示例：

```text
总体 Agent：EICAD 工程智能助手
本次调用 Agent：路基模板创建 Agent
```

---

### 5.3 当前项目上下文

包括：

```text
项目 ID；
项目名称；
项目类型；
设计阶段；
客户 / 项目配置；
默认设计标准；
默认单位；
当前路线；
当前专业模块。
```

MVP 可以先只加载：

```text
当前工程 ID；
当前工程名称；
当前路线 ID；
当前模块；
项目默认参数。
```

---

### 5.4 当前软件上下文

包括：

```text
软件名称；
软件版本；
当前模块；
当前命令环境；
当前打开文件；
是否只读；
是否允许写入；
是否存在未保存变更。
```

示例：

```text
软件：EICAD
模块：横断面 / 路基模板
工程状态：可编辑
```

---

### 5.5 当前选中对象上下文

包括：

```text
当前路线；
当前断面；
当前模板；
当前桩号；
当前选中图元；
当前工程对象 ID；
对象类型；
对象摘要。
```

注意：

```text
不要把完整几何数据直接塞给模型；
优先传结构化摘要；
需要详细数据时通过工具按需读取。
```

---

### 5.6 当前工作流状态

包括：

```text
当前 run_id；
当前 workflow_state；
上一状态；
下一候选状态；
是否等待用户输入；
是否等待审批；
是否处于失败状态；
是否支持恢复。
```

---

### 5.7 当前草稿对象

在参数提取、规则补全、DryRun 前，系统会形成 Draft Object。

上下文应包含：

```text
已提取参数；
已确认参数；
默认补全参数；
规则推导参数；
缺失字段；
字段来源；
字段置信度。
```

---

### 5.8 可用工具列表

上下文中可以包含本次 Agent 可用工具，但必须经过裁剪。

包括：

```text
工具名称；
工具描述；
工具输入 Schema；
工具风险等级；
是否支持 DryRun；
是否需要审批。
```

注意：

```text
只给模型当前业务 Agent 被授权的工具；
不要把全系统所有工具都给模型；
不要给未注册工具；
不要给高风险工具的直接执行权限。
```

---

### 5.9 用户权限上下文

包括：

```text
用户角色；
是否允许执行当前 Agent；
是否允许使用当前模型；
是否允许调用写入工具；
是否允许保存工程；
是否允许查看 Trace。
```

MVP 中可以先简化为：

```text
普通用户；
管理员；
只读模式；
可执行模式。
```

---

### 5.10 历史对话摘要

包括：

```text
当前任务相关的最近对话；
用户已经补充过的参数；
用户已经确认过的选择；
上一次失败原因；
当前任务摘要。
```

MVP 不建议把完整长对话都塞给模型。

建议使用：

```text
最近 N 轮对话 + 当前任务摘要
```

---

## 6. 哪些信息不应该直接进入上下文

MVP 中，以下内容不建议直接给模型：

```text
完整工程原始文件；
完整 CAD 图元数据；
完整横断面几何点集；
完整项目数据库；
敏感客户数据；
API Key；
软件内部路径；
无关历史对话；
未授权工具；
未确认的模型猜测结论。
```

原则：

```text
给模型摘要，不给模型全量；
给模型引用，不给模型原始大数据；
给模型当前任务相关内容，不给无关工程内容；
需要详细数据时，通过受控工具读取。
```

---

## 7. 上下文来源标记

Context Package 中的重要字段必须有来源标记。

来源包括：

```text
user_input：用户输入；
system_context：软件上下文；
project_config：项目配置；
agent_config：Agent 配置；
workflow_state：工作流状态；
tool_result：工具读取结果；
rule_result：规则结果；
manual_confirmed：用户确认；
conversation_summary：对话摘要。
```

这样后续参数展示、规则解释、Trace 回放都可以说明来源。

---

## 8. Context Manager 与其他模块的关系

Context Manager 依赖：

```text
前端提交信息；
Agent 配置中心；
软件 Adapter 的只读查询接口；
项目配置；
会话状态；
工具注册表；
权限配置；
Trace Logger。
```

Context Manager 服务于：

```text
IntentRouter；
AgentRouter；
模型网关；
参数提取；
Schema 校验；
规则引擎；
工具计划；
DryRun；
结果解释；
Trace 回放。
```

Context Manager 不能直接：

```text
调用大模型；
执行工程工具；
修改工程数据；
决定规则结果；
替代用户审批；
替代 Tool Registry。
```

---

## 9. MVP 不做范围

上下文管理 MVP 暂不做：

```text
复杂长期记忆；
跨项目记忆；
客户画像；
组织级知识沉淀；
自动学习用户习惯；
大规模向量记忆；
复杂上下文压缩算法；
完整工程数据索引。
```

但需要预留：

```text
长期记忆接口；
项目记忆接口；
客户配置接口；
知识检索接口；
上下文摘要接口；
上下文脱敏接口；
上下文版本记录。
```

---

## 10. MVP 验收标准

本模块完成后，应满足：

```text
1. 每次运行能生成 Context Package；
2. Context Package 包含用户输入、Agent、项目、模块、对象、状态；
3. 模型调用前必须通过 Context Package 构造上下文；
4. 上下文只包含当前任务必要信息；
5. 当前选中对象能以摘要方式进入上下文；
6. 可用工具列表能按当前业务 Agent 裁剪；
7. 用户确认过的信息能进入上下文；
8. 缺失参数能在上下文中体现；
9. 上下文字段有来源标记；
10. 上下文能写入 Trace；
11. 敏感数据和 API Key 不进入上下文；
12. 后续新增业务 Agent 时，可以复用上下文构造机制。
```

---

## 11. 本模块结论

上下文管理层的核心不是“给模型越多信息越好”，而是：

```text
给模型完成当前任务所需的最小、准确、结构化、可追踪信息。
```

正确设计应是：

```text
前端提供用户输入和当前环境；
配置中心提供 Agent 配置；
Adapter 提供工程对象摘要；
Context Manager 组装 Context Package；
模型只基于 Context Package 进行理解和提取；
详细工程数据通过受控工具按需读取。
```

一句话：

```text
上下文管理层是模型理解工程环境的入口，也是防止模型拿到过多不受控工程数据的闸门。
```
