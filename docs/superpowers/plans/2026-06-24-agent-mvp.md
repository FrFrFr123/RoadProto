# Agent MVP Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 完整实现 RoadProto 可控工程 Agent 的 MVP：独立后端仓库 `F:\0_GPT_RoadProtoAgentBackend` 负责 Agent 编排、模型调用、任务状态和审计日志；当前 RoadProto 仓库 `F:\0_GPT_道路设计原型功能项目` 新增相对独立的 `AGENT` 模块，提供 AutoCAD/WPF 停靠式 Agent 控制台、后端自动启动、HTTP 通信、用户确认、全链路日志和路基模板创建验证流程。

**Architecture:** 采用“独立 Agent 后端 + RoadProto 本地薄集成”的结构。后端使用 `.NET 8 / ASP.NET Core` 提供本机 HTTP API，监听 `http://127.0.0.1:17861`，保存任务、配置、模型 Provider 和日志；RoadProto 侧新增 C++ `AGENT` 模块注册命令与本地 CAD 工具适配，WPF 托管插件提供可停靠 Palette 控制台、设置、日志查看和 HTTP 客户端。WPF 不直接写 CAD 核心业务，不新增独立 Web 页面，不使用 WebView。

**Tech Stack:** RoadProto 侧保持 C++17 / ObjectARX 2021 / .NET Framework 4.8 WPF / MSBuild；Agent 后端使用 `.NET 8 / ASP.NET Core`、内置 `HttpClient`、`System.Text.Json`、Windows DPAPI、文件日志；测试使用现有 C++ 核心测试、托管桥接测试，以及后端 `dotnet test`。

## 3. 后端 Agent 任务状态机和模型网关

**目标:** 后端具备从用户自然语言输入到结构化执行计划的 MVP 编排能力。MVP 先支持“路基模板创建”一个 Agent，用可替换模型网关和规则兜底生成计划。

- `F:\0_GPT_RoadProtoAgentBackend\src\RoadProtoAgentBackend.Infrastructure\Models\OpenAiCompatibleModelGateway.cs`
- `F:\0_GPT_RoadProtoAgentBackend\src\RoadProtoAgentBackend.Application\Agents\SubgradeTemplateCreateAgent.cs`
- `F:\0_GPT_RoadProtoAgentBackend\src\RoadProtoAgentBackend.Api\Endpoints\AgentRunEndpoints.cs`

**状态机:**

- `Created`：收到用户请求。
- `Planning`：正在整理上下文和生成计划。
- `AwaitingUserConfirmation`：需要用户确认写入 CAD。
- `DispatchingTool`：RoadProto 侧正在执行本地工具。
- `Succeeded`：工具执行成功。
- `Failed`：流程失败。
- `Cancelled`：用户取消。

**HTTP 合约:**

- `POST /api/agent/sessions` 创建会话。
- `POST /api/agent/runs` 提交用户消息，返回 `TraceId`、`SessionId`、`TaskId` 和初始状态。
- `GET /api/agent/runs/{taskId}` 获取任务当前状态、计划、事件。
- `POST /api/agent/runs/{taskId}/confirm` 用户确认执行。
- `POST /api/agent/runs/{taskId}/tool-result` RoadProto 回传本地工具执行结果。
- `POST /api/agent/runs/{taskId}/cancel` 用户取消。

**实施步骤:**

- [ ] 定义统一 ID 生成规则：`TraceId` 每次用户请求一个，`SessionId` 每个面板会话一个，`TaskId` 每个 Agent 任务一个。
- [ ] 实现内存任务仓库，MVP 先不引入数据库；任务事件同时追加到日志。
- [ ] 实现 `OpenAiCompatibleModelGateway`，用 OpenAI 兼容请求格式适配 DeepSeek、Qwen、GLM、GPT。
- [ ] 模型不可用时，`SubgradeTemplateCreateAgent` 使用规则兜底解析，仍能生成可确认的路基模板计划。
- [ ] 结构化计划必须包含：模板名称、车道/路肩/边坡参数、单位、默认值来源、待用户确认的 CAD 写入动作。
- [ ] 所有状态迁移都写入 JSON Lines 日志。

**模型 Provider 默认 BaseUrl 建议:**

- `DeepSeek`: `https://api.deepseek.com`
- `Qwen`: `https://dashscope.aliyuncs.com/compatible-mode/v1`
- `GLM`: `https://open.bigmodel.cn/api/paas/v4`
- `GPT`: `https://api.openai.com/v1`

**验证:**

- [ ] 单元测试覆盖状态迁移、确认前不下发工具、取消后不可执行。
- [ ] 单元测试覆盖四类 Provider 的请求 URL 和 Authorization header 组装。
- [ ] 手动调用 `POST /api/agent/runs`，确认返回计划和 `AwaitingUserConfirmation` 状态。
- [ ] 手动检查日志，确认每个阶段都有 `TraceId`、`SessionId`、`TaskId`。

## 10. 风险和处理方式

- [ ] **后端 exe 不存在。** WPF 进入开发模式启动 `dotnet run --project`，并在 UI 明确显示当前使用开发模式；发布验收必须补齐 exe。
- [ ] **端口 `17861` 被占用。** 后端启动失败时输出占用错误；MVP 不自动换端口，避免 WPF 和后端配置漂移。
- [ ] **模型 Provider API 格式差异。** MVP 使用 OpenAI-compatible 接口；不兼容细节放在 `IModelGateway` 适配层，不影响 RoadProto。
- [ ] **模型输出不稳定。** `SubgradeTemplateCreateAgent` 必须有规则兜底和参数校验，确认前只展示计划，不写 CAD。
- [ ] **WPF 与 ObjectARX 线程上下文问题。** CAD 写入必须通过现有命令/Bridge/Adapter 路径进入 AutoCAD 合法执行上下文。
- [ ] **日志量增长过快。** 后端和 RoadProto 两侧都执行 `14` 天或 `1GB` 清理策略；日志面板只加载当前 TraceId 相关内容。
- [ ] **文档与实现脱节。** 每完成一个阶段同步更新 RoadProto `docs/agent`、模块文档、业务文档、复用文档和版本记录。
