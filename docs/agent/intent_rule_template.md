# Agent 意图规则文档模板

本文档定义 RoadProto 可控工程 Agent 的意图规则文档固定格式。每一个可独立识别、校验、确认和执行的用户意图，都必须按本模板单独成文。

意图文档必须挂在明确 Skill 下。新增业务能力时，先写 `docs/agent/skills/<skill>_skill.md`，再写本目录下的意图文档。不得让意图脱离 Skill 直接绑定 Tool。

意图文档统一放在：

```text
docs/agent/intents/
```

创建、修改、查询、删除、诊断、配置类意图必须拆分为不同文档，不得长期混写在同一份意图文档中。通用说明可以放在本模板或 Agent 总览文档里，具体规则必须落到对应意图文档。

## 文档命名规则

建议使用：

```text
<业务对象>_<动作>.md
```

示例：

```text
subgrade_template_create.md
subgrade_template_modify.md
subgrade_template_query.md
subgrade_template_delete.md
```

## 固定章节

每份意图文档必须包含以下章节。

### 1. 意图基本信息

必须说明：

- 意图 ID。
- 所属 Agent。
- 所属 Skill。
- 所属 RoadProto 模块。
- Skill 文档。
- 关联业务文档。
- 关联 RoadProto 既有功能文档。
- 当前状态。

本节必须体现十二层流程中的归属关系：

```text
Agent -> Skill -> Intent -> Schema -> Rule -> Tool -> Adapter -> Execution -> Trace
```

### 2. 用户表达

必须说明：

- 用户可能如何表达。
- 明确不应匹配的表达。

不应匹配表达要覆盖相邻意图，尤其是创建和修改、查询和执行、配置和业务动作之间的边界。

### 3. 意图边界

必须说明：

- 本意图负责什么。
- 本意图不负责什么。

边界说明必须能用于路由和拒绝执行，不只做业务介绍。

### 4. 必要参数

必须列出执行本意图的最小参数集合。

每个必要参数至少说明：

- 参数名。
- 类型。
- 是否必填。
- 来源。
- 缺失时处理方式。

写 CAD、修改 DWG、删除对象、覆盖配置等动作，必须把用户确认作为必要前置条件。

### 5. 可选参数

必须列出用户可以覆盖、系统可以补全、后续可以扩展的参数。

每个可选参数至少说明：

- 参数名。
- 类型。
- 默认值来源。
- 说明。

如果某个参数当前只展示、不参与执行，必须明确说明，避免 Agent 误认为可以自由推导或写入。

### 6. 默认值规则

必须说明：

- 默认值由哪个规则、Schema、领域模型或既有功能生成。
- 用户明确输入时如何覆盖。
- 未提及参数如何保持默认。
- 哪些默认值禁止由 LLM 自行臆造。

LLM 只能抽取和解释用户表达，默认值补全必须由规则层或 RoadProto 领域能力完成。

### 7. 校验规则

必须说明：

- Schema 校验。
- 领域规则校验。
- CAD 写入前校验。
- 风险阻断条件。

校验失败必须返回可定位原因，不允许静默修正高风险参数。

### 8. 追问规则

必须说明：

- 哪些信息缺失时必须追问。
- 哪些表达歧义时必须追问。
- 推荐追问话术。

当参数缺失可以安全使用默认值时，不追问；当默认值会改变用户意图或影响 CAD 写入风险时，必须追问。

### 9. 确认前展示

必须说明 WPF 确认页展示内容。

写入类动作至少展示：

- 意图名称。
- 参数摘要。
- 默认值来源。
- 用户覆盖项。
- 风险等级。
- 将调用的 Tool。
- 将创建或修改的 CAD 对象。
- `TraceId` / `TaskId`。

用户确认前允许修改的参数，也必须在本节列出。

### 10. 工具绑定

必须说明：

- 后端 Tool 名称。
- 后端参数 Schema。
- RoadProto 本地适配入口。
- 是否写 CAD。
- 是否必须用户确认。
- Tool 和 RoadProto 既有命令、Bridge、Adapter 的边界。
- Tool 是否在所属 Skill 的白名单中。

外置后端不得直接写 DWG。所有 CAD 动作必须经过 RoadProto 本地 `AGENT` 模块和 ObjectARX Adapter。

### 11. 执行结果

必须说明：

- 成功返回内容。
- 失败返回内容。
- 是否包含预览数据。
- 是否包含 CAD 实体 handle 或对象 ID。
- 是否支持回滚或人工处理建议。

### 12. 日志与 Trace

必须说明每个意图必须记录的阶段。

写入类动作至少记录：

- 意图识别。
- 参数抽取。
- 默认值补全。
- 参数校验。
- DryRun。
- 用户确认。
- Tool 调用。
- RoadProto 本地 Adapter 执行。
- 结果返回。
- 错误、取消和重试。

日志不得记录明文 API Key，不得泄露敏感配置。
